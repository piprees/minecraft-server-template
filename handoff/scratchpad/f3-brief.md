## Build (generic; no code naming a dimension)
1. **Levels.** `/customdim fastrender <slug> pyramid [tile] [threads] [maxLevel]`: level 0 is the whole player border in one tile (default 512 px, stride = border diameter / 512); each next level halves the stride, split into 2×2 tiles of the same pixel size, down to stride 1 or `maxLevel`. Each tile writes the layers the fast render already writes (map colour with hillshade, height, biome; roof-off for roofed worlds; a per-tier layer for sky worlds) as PNG, in a folder layout a standard deep-zoom viewer reads (`<layer>/<z>/<x>/<y>.png`), plus `pyramid.json` (border, levels, strides, tile size, layers, timings per level, legend).
2. **Coarse first.** Level 0, then level 1, … each written as soon as done, so a whole-world image exists after the first level. Measure and report the time to level 0 and each level on the three bench dimensions.
3. **Cheap first wave.** Find whether a coarse level can use a cheaper column (the router's preliminary surface for surface worlds, or a scout-only run list) without misleading the map; measure its agreement with the full answer at that stride (heights within ±1, biomes) and the speed-up; use it for levels coarser than a cut-off only if heights stay ≥ 95% within one stride-unit and biomes ≥ 99%; say what it does on roofed and sky worlds.
4. **Tiles on demand.** `/customdim fastrender <slug> tile <z> <x> <y>` renders one tile at any level (the zoom path), with its timing.
5. **Reuse.** Coarse levels sample columns the finer levels also sample: reuse them (a column at stride s is a column at stride s/2), and report the saving.
6. **Bench.** Extend `runFastBench` with a pyramid mode; numbers for overworld, the_aviary and the_underdark at the logged seeds (F2's brief: 4705305050088502262, 7826077224469180302, 2070195577671787983).
7. **A viewer page** for the owner is NOT in scope (look and feel is the owner's choice): write the pyramid so a small static deep-zoom page could show it, and describe in your report what such a page needs.
