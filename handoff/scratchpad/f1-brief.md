1. Under `server/src/main/java/.../render/fast/` (beside the existing `Sampler`, `RenderFiles`, `RenderLayers`; read them and `/customdim render` first): a per-thread tile sampler built from the level's random state, noise settings and biome source as RuntimeRegistry left them; batch sampling (26.3's volume sampling, as seedlod uses it) of the FULL final density; a scout pass on cell corners to find occupied bands, then crossings refined by bisection; **multi-run columns** (top and bottom of each solid run, capped ~24) so one model serves every preset with no branching on the dimension's key; stride 1–16; biome per quart from the level's own source; the compiled material rule for each run's top block (and bottom, for roofs); fluids from the level's own picker at each open run's lowest block if that can be done without a chunk (R1 open question 4: find out; otherwise sea-level and lava-level from the noise settings, labelled as such); structure footprints from `Sampler.starts` (which honours our structure control).
2. Command `/customdim fastrender <slug> [stride] [threads]`: writes the same PNG/JSON shapes the existing render writes (heights, map colour, biome) plus: hillshade; for roofed worlds a roof-off layer (floor under the first ceiling) and a cut-at-Y layer; for sky worlds one layer per run index (tiers); a run-list dump (binary or compact JSON) for later oblique rendering; timings (columns/s, threads, stride) in the JSON.
