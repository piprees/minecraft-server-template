## Deliverable: `docs/design/rebuild-26/places/` (small files, plain Markdown, British English, current state only)
1. `README.md` — the plan in one page: what a place is (the owner's ruling), the three sources (pack structure mods placed by our control; explorify through dep-review; our own set pieces), the work packages in order with sizes, and what the owner decides.
2. `inventory.md` — every structure theme the 1.21.1 pack had, by theme (ruins, dungeons, towers, villages and camps, Nether, End, sky, underground, ocean), with what 26.3 has for it now (ids), what is lost, and which dimensions' 1.21.1 configs and descriptions wanted it. The gap list is the input to our set pieces.
3. `set-pieces.md` — a design for our own set-pieces kit, generic and data-driven, no code naming a dimension: what a set piece is in the definition schema (proposed fields), how it is built at worldgen time from vanilla blocks and vanilla templates (vanilla's own `StructureTemplateManager` templates such as end city ships, fossils, ruined portals, ancient city pieces may be reused by id — say which and how; nothing copied into the repo), how pieces compose (procedural shapes: craters, scatters, pits, falls, walls, camps, farms, chains/pipes/chimneys; spawners; loot; named mobs as easter eggs), how they sit on terrain (ground, over void, under a roof, on a pit wall), how they are placed (our structure control: groups, wants, force), how the survey, shots and the web map find them (so review shots show places). Size it in work packages (K-sized, ~180 steps each), each with acceptance tests. Read the existing structure runtime (`StructureRuntime`, `StructurePlacements`, `StructureSites`, `PinnedGround`) so the design extends what exists.
4. `dimensions.md` — for every one of the 82 dimensions: its places (named, one line each) drawn from its description and 1.21.1 config, the owner's notes where given (Batches 1–2 verbatim intent), and for each place its source (an available structure id, explorify, or a set piece from set-pieces.md). Group by batch (`fidelity/batches.md`).
5. `explorify.md` — the dependency checklist (`DEPENDENCIES.md` § Adding a mod) run as far as it can be without a boot: version, licence, side, dependencies, what it registers, the steps to add it to `config/modrinth-mods-26.3.txt` and the register. Do not edit the mod list.
