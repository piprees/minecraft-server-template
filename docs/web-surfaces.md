# Web surfaces (styles & markup)

The public pages share one design system but have **no shared stylesheet** — each surface carries its own copy of the styles. [`DESIGN.md`](../DESIGN.md) is the source of truth for tokens (the Quarry palette, type scale, spacing); every copy is kept in step by hand.

Restyling any cloud surface: use the `web-surface-branding` skill, which covers the four cloud surfaces in detail. This file adds the surface map, the local-only seeds page, and the nav rules that span both nginx templates.

| Surface | Markup + styles live in | Regenerated by | Deploy tier |
| --- | --- | --- | --- |
| pack.DOMAIN | `modpack/template/index.html` (full page, CSS custom properties) | `build-modpack.sh` → `modpack/dist/index.html` (CI after full deploys) | Pull (CI rebuilds pack) |
| mods.DOMAIN | HTML/CSS heredocs in `scripts/check-updates.sh` (`--html`) | mod-checker container on boot + daily 06:00 UTC → `modpack/dist/status.html` (nav-proxy rewrites `/` → `/status.html`) | Infra (force-recreates mod-checker) |
| status.DOMAIN | Uptime Kuma + `customCSS`/`footerText` in `config/uptime-kuma/kuma-config.json`, applied by `scripts/kuma-provision.py` (kuma-init, every deploy) | kuma-init container | Infra (force-recreates kuma-init) |
| map.DOMAIN | uNmINeD viewer shell in `docker/unmined-render/webshell/`; nav + OG injected by `nav-proxy.conf.template` | `unmined-render` sidecar → `data/unmined-web/` | Infra (force-recreates nav-proxy) |
| seeds.DOMAIN | **Local profile only.** Page hosted by the mod (`web/SeedServer`, `SEED_VIEWER_PORT`; unset means off); markup and styles are jar resources under `mods/custom-dimensions/src/main/resources/seed-viewer/`; nav injected by `config/nginx/nav-proxy-seeds.conf.template` | a mod rebuild — and `mods/custom-dimensions/build-viewer-css.sh` first for a CSS change, since `web/app.css` is Tailwind source and the jar ships `web/app.built.css` | Local only — never deployed |
| 404 page | Heredoc in `scripts/build-modpack.sh` → `modpack/dist/404.html` | `build-modpack.sh` | Pull |

**The nav bar is injected, not authored per page.** `config/nginx/nav-proxy.conf` `sub_filter`s the nav HTML + CSS into every page — **five near-identical copies**, one per `server` block, across two files (four in `nav-proxy.conf.template`, one in `nav-proxy-seeds.conf.template`). Changing the nav MARKUP means changing all five: `grep -c '<nav' config/nginx/nav-proxy.conf.template config/nginx/nav-proxy-seeds.conf.template`.

**Adding a nav ENTRY is one variable, not five edits.** Every nav carries a `${NAV_EXTRA_LINKS}` slot; set it once on nav-proxy and the link appears on every surface. Nav hrefs are `${NAV_SCHEME}://<sub>.${DOMAIN}${NAV_PORT}` — cloud leaves them `https://` with no port, the local profile sets `http` and `:${WEB_PORT}`. All three must stay DEFINED even when empty: nginx's envsubst only substitutes variables present in the environment and leaves an undefined `${...}` literal in the rendered config.

**`seeds.DOMAIN` is local-profile only and must stay that way.** The roller has no authentication, can teleport a player, and writes rolled winners into the committed overlay. Its server block lives in a separate file (`nav-proxy-seeds.conf.template`) that only `docker-compose.local.yml`'s nav-proxy `command` stages — the cloud profile never renders it. Do not merge it into `nav-proxy.conf.template`.

**Footer version string** (`<PackName> · <pack>-<MC_VERSION>-v<git sha>`): `PACK_NAME` is computed by `build-modpack.sh` from `git rev-parse --short HEAD` and baked into the pack page. The mods page (`check-updates.sh`) and status page (`kuma-provision.py`) run in containers with no git checkout, so they read the _served_ pack build instead — `modpack/dist/packwiz/pack.toml` (`version = "<sha>"`), via the dist mount and `http://pack-web/packwiz/pack.toml` respectively. A status footer showing `vunknown` means pack-web was unreachable and no git checkout existed.

**Fonts:** the placeholder uses system fonts throughout. To add a custom display font, place the woff2 in `modpack/template/fonts/` (copied to `dist/fonts/` by the build), update the CSS in each surface, and add a CORS header on `/fonts/` in `pack-web.conf` if Kuma's customCSS loads it cross-origin from pack.DOMAIN.

OG/meta tags are injected per-domain by `nav-proxy.conf` (`sub_filter '<title>'`). Kuma's own markup can only be restyled via `customCSS` in `kuma-config.json` — its HTML is not editable.
