## Gotchas — every one of these cost real time

1. **A stale world makes every structure assertion measure history.**
   Worldgen is creation-time-only ([D2](../../TROUBLESHOOTING.md#d2)); the
   generator is serialised into `level.dat` and `registerDimensions` skips
   keys already in the registry. A jungle dimension "failed" its biome-filter
   check with igloos in its pool — the filter was correct and the world was
   several configs old. Only **15 of 78** dimensions were building fresh
   biome sources; after a `data/world` wipe it was 75.
   **Run `scripts/check-dimension-drift.py` first, always.**
2. **`structures.noise` needs an mc restart, but NOT a world wipe.** Config
   is read at boot; placement is rebuilt from it on every world load. Editing
   it and re-dumping a census without restarting gives the old groups and
   looks exactly like the edit did nothing.
3. **`structure-census` needs a fully-qualified dimension id** — fixed now
   (a bare name resolves against the configured namespace), but any OTHER
   `customdim` subcommand taking an identifier may still have the old
   behaviour: a bare name becomes `minecraft:<name>` and answers "Dimension
   not loaded" while the dimension is sitting there loaded.
4. **Dimensions idle-unload after 5 minutes.** Pair every
   `customdim load <slug>` with its census immediately; a batch of loads
   followed by a batch of censuses will fail on the ones that timed out.
5. **`_census_task` and multiprocessing.** Any module loaded by path via
   importlib whose functions go to a `Pool` MUST be registered in
   `sys.modules` under the spec name first, or the child dies with
   "No module named ...". Running the script directly hides it (the function
   is in `__main__`).
6. **Two concurrent rescores will fight over the same candidate stores.** A
   `nohup ... &` job survived a tool call I thought had killed it and ran for
   35 minutes alongside the tracked one, halving throughput. Check
   `pgrep -f score-dimensions` before starting a long job.
7. **The census backfill saturates every core.** Use `--census-workers N`
   to leave room; a local Minecraft boot took three times as long beside it.
   Progress prints an ETA every 5% — no output means an older build, not a
   hung job.
8. **`generation_payload()` returns None without a `type`**, which is why
   base worlds have no fingerprint and no census — and why the spike's
   "`the_end` >= 60" assertion could never pass. See the open spike.
9. **F3's `noisePlacement` fingerprint key never reached a real config**
   until this session: `monolith_from_dir` scanned the staged overlay through
   `load_dimension_configs`, which re-pointed the noise type-defaults at a
   directory that has none, so every `load_config()` ended with them nulled.
   The unit tests passed because they set the directory by hand. **A test
   that reproduces the production wiring by hand tests the maths, not the
   wiring** — this shape of bug appeared three times in this spike.
10. **Nested datapack paths mint bogus set ids.** `load_structure_sets`
    derives the namespace from the first `data/` segment, so
    `…/data/structures/data/dungeons_arise/…` becomes
    `structures:major_structures`. Whichever copy the filesystem yielded
    first won the map, silently sending a whole mod back to grid scoring.
11. **New seed-roller modules must be added to `build-stack-bundle.sh`'s
    MANIFEST.** `noise_placement.py` (from F1) and `census_scoring.py` were
    both missing; `./dev seed-roll` would have died on import on every
    consumer. `test-scripts.sh --quick` catches it.
12. **`./dev verify` reaches consumers only after a release.** The consumer's
    `.stack/current` bundle is whatever version it pulled; run the template's
    `scripts/check-*.py` directly against the consumer's `data/` until then.

## Open work

**`docs/spikes/SPIKE-BASE-WORLD-PARITY.md`** — the mod owns base-world seeds,
borders and difficulty, but `DimensionStructures.transformed` gates on
managed NAMESPACE and base worlds are deliberately excluded from that set, so
the overworld / nether / end / paradise_lost get no noise placement, no
`structureDensity` and no forced placements at all.

**Decide before coding.** The Nether gates progression on fortresses (blaze
rods) and the End on end cities (elytra); dissolving those grids into a
`sparse` group could push them out of reach. The spike proposes opt-in per
base world, default off, with a reachability floor asserted by
`check-noise-regression.py` as the gate.

Also open, lower priority: 9 dimensions previously had 22 wants for groups
their world type never enabled — fixed by naming the groups explicitly, and
now guarded by the unsatisfiable-want audit in `check-noise-regression.py`.
Worth re-running after any structure-mod pin bump.
